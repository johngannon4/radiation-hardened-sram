# Python analysis

`sram_analysis.ipynb` post-processes the CSVs written by the OCEAN sweeps and produces the
trade-off figures in the paper: the Q<sub>crit</sub> sizing heatmap, the temperature trend, and
the leakage-power / Q<sub>crit</sub> Pareto frontier with its knee point.

```bash
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt
jupyter lab sram_analysis.ipynb                      # run from this directory
```

Paths are resolved relative to the notebook's own directory, so it has to be run from
`analysis/`. Figures and summary tables are written to `analysis/results/`, which is
gitignored because it is fully regenerated by a run.

## Layout

| Path | Contents |
|---|---|
| `sram_analysis.ipynb` | The analysis, with its outputs committed so it reads on GitHub without being run |
| `src/io_utils.py` | Loaders for Cadence CSV exports — two-column waveforms, and multi-(X,Y)-pair files |
| `src/metrics.py` | Edge timing, 50 % delay, current/energy integration, SEU dip and recovery, SNM proxy |
| `src/analysis.py` | Runs the waveform pipeline over `data/` and returns tidy summary frames |
| `src/plotting.py` | Transient, SEU-case, and SNM curve plots |
| `src/corner_analysis.py` | Corner dataset loading and a simple power/robustness trade-off score |

## Datasets

Three generations of sweep, matching the three directories in [`../ocean/`](../ocean/). All were
written by appending one row per simulation, so a crashed batch could be resumed without
losing completed points.

**Full PVT sweep** — sizing × temperature × V<sub>DD</sub> × corner:

| File | Rows | Contents |
|---|---|---|
| `dice_seu_full_sim.csv` | 9,000 | One Q<sub>crit</sub> per point: 6 × 6 sizing × 5 temp × 5 V<sub>DD</sub> × 5 corners × 2 polarities |
| `dice_power_full_sim.csv` | 4,500 | One leakage figure per sizing / temp / V<sub>DD</sub> / corner point |
| `dice_snm_full_sim.csv` | 793,114 | Butterfly sweeps at 221 samples per point, over 3,592 sizing / temp / V<sub>DD</sub> / corner points |

**Corner sweep** at nominal V<sub>DD</sub> — `dice_seu_corners.csv` (1,800 points, coarse
bracketing with a `flipped` flag per injected charge), `dice_power_corners.csv` (900),
`dice_snm_corners.csv` (900 × 221). `dice_power_corners.csv` contains one repeated header row
from the append-mode writes; the notebook strips it.

**TT-only sweep** — `dice_seu_results.csv` (360), `dice_power_results.csv` (180),
`dice_snm_results.csv` (180 × 221).

**Waveform exports** used by the early pipeline: `10T_Test_D.csv`, `10T_Test_D2.csv`,
`10T_Test_I.csv`, `N0_Test.csv`, `QB1_TEST_CSV.csv`, `Quatro_SNM_test.csv`.

**Butterfly-curve exports** for the minimum-sized comparison: `baseline_snm_full.csv` (6T),
`rsp_snm_full_sim.csv` and `rsp_snm_sweep{1,2}.csv` (14T RSP), and `snm_exports/` (12T DICE and
10T Quatro VTC branches, exported directly from the ADE waveform viewer).

### Column notes

`corner`, `wn_store`, `wp_store`, `wn_access` (widths in metres), `temp` (°C), `vdd` (V),
`polarity` (1 = storing 1, 0 = storing 0).

- **`qcrit_fC` is in coulombs, not femtocoulombs**, despite the name — `8.47e-15` is 8.47 fC.
- `leakage_power_W` is in watts; `Vn` / `N0` are the butterfly sweep input and output voltages.

## Trade-off analysis

The power, SEU, and SNM tables are merged on sizing, temperature, and corner, then used to
compute the Pareto frontier of leakage power against Q<sub>crit</sub> and its knee point —
W<sub>n</sub> = 320 nm, W<sub>p</sub> = 120 nm at −40 °C. The merged frame is large enough that
the plotting cells sample it rather than rendering every row.
